# Free2Z UI formatting inventory

`tests/formatting-inventory.json` is the Free2Z UI maintainers' owned inventory and shrinking baseline. Every entry records the source file, complete normalized call, fingerprint, classification and rationale. `node scripts/check-formatting-inventory.mjs` parses Svelte component ASTs and TypeScript/JavaScript ASTs across `src/`. It checks executable `Intl` formatting, locale case conversion, `toLocale*`, `localeCompare`, ISO serialization, and `date-fns` imports; comments and type-only references are not calls. The checker is run by `npm test`, including disposable negative controls. An added or changed call fails until it is removed or explicitly classified; removing a site requires removing its stale entry. The checker caps the inventory at 107 sites and the legacy class at 55; lower the relevant caps when entries are removed. Do not regenerate the baseline wholesale.

At this revision there are 107 sites: 6 shared implementations, 10 fixed-precision sites, 10 machine/protocol sites, 26 specialized sites, and 55 legacy sites. The baseline gives the exact call for each. The legacy entries are outstanding migration work, not proof that direct formatting is centralized. Their migration must preserve each call's options, numeric precision, and the meaning of its input. In particular, billing values need their units and rounding independently verified; language-name formatters handle arbitrary content-language tags and cannot blindly use the UI-only locale normalizer.

Fixed-precision sites retain decimal strings or BigInt and obtain grouping or separators without converting the value to a float. The `en-US` plain-decimal formatter in `format-tuzis.ts` is an internal decimal conversion, not a viewer-language choice. Machine sites include stable identifier ordering and UTC serialization. Specialized entries cover tag canonicalization, grapheme boundaries, comparison case normalization, timezone discovery, and a date error fallback. Preserve their semantics when touching them.

A general currency or unit API is intentionally not introduced here: currency precision differs between fixed-point ledger strings and already-numeric presentation values, while unit callers use different scaling and rounding. The next migration must define those contracts and test exact large and fractional values before replacing the existing paths. This inventory is syntactic, not whole-program dataflow analysis; references that extract an Intl constructor or object are also guarded as escape sites, but other indirect dataflow still needs review.
