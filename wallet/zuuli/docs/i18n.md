# ZUULI internationalization

ZUULI uses the existing `i18next`, `react-i18next`, and `i18next-icu` kernel.
ICU MessageFormat supplies CLDR plurals and selects; React `Trans` retains
markup in complete messages. Each en/es/fr catalog is a separate lazy import.
The default bundle does not import the other catalogs. Locale resolution still
prefers the persisted locale, then the browser, then English. No locale writer
or selector is introduced here; that work belongs to #326.

## Message ownership and error boundaries

Declare a key in `src/i18n/messages.ts` and add it to all three catalogs. Keep
interpolation in one message. Counts use ICU `plural`, not English suffixes.
Translated markup contains only named React component slots. User-controlled
TOTP usernames remain React children in a component slot, so they cannot become
translation markup.

Every render owner uses `useTranslation` (locally imported as `useUiTranslation`)
and its bound `uiT` function. This subscribes mounted labels, markup and parents
that read static descriptor getters to language changes. Getter tables remain
lazy; they are re-read by a subscribed parent. The imperative `translate()`
helper is for event handlers and non-React presenters only. Long-lived wallet
and recovery effects read the active locale at event time rather than capturing
a bound translator or restarting native work when the language changes.

Inline errors use `useMessageError`: state holds an allowlisted message key,
not a translated snapshot or a backend body. Existing errors retranslate when
the active instance changes language. Toast snapshots are dismissed on a
language change. User-entered text and reviewed outgoing feedback drafts remain
data; changing language does not rewrite them. About uses the same active
instance as the other routes. Its injected message-table API remains available,
and pseudo-expansion generation now lives in a test-support module outside the
shipping import closure.

Callers must lazy-load a supported catalog with `loadCatalog` and register its
resource bundle before calling the active instance's `changeLanguage`. The
kernel updates the document language and existing Intl date helpers on that
event. This change provides no language selector or preference writer (#326).

`src/i18n/errors.ts` accepts typed `UiError` keys for authored frontend
precondition failures and maps structured HTTP 401/403/429 statuses and otherwise uses
a caller-authored localized fallback. Native diagnostics, arbitrary thrown
strings, backend error bodies and stacks are never display authority. Auth,
OAuth/checkout recovery, wallet operations, sync, maintenance and preserved
wallet preview apply this boundary. Backend error text and protocol contracts
remain unchanged; specific donation failure classification still maps its
existing machine contract to owned localized messages.

## Formatting and deliberate exceptions

`formatDate` retains explicit date/time options; `timeAgo` retains
`Intl.RelativeTimeFormat` and an explicit calendar-date context. Platform-credit/USD/block-height formatting and whole-2Z parsing retain
their existing browser-locale behavior, including restored canonical drafts
when the browser language has no catalog. **ZEC input and canonical output remain ASCII:** Western digits, `.`,
no grouping, eight-decimal zatoshi precision. No localized display value feeds
transaction construction, signatures, retry bytes or protocol identifiers.

The source check has narrow, explicit exceptions:

- The three literal messages in `src/app-bootstrap.tsx` are the dependency-free
  crash frame. It must render even when locale loading itself fails.
- Exact product/provider/OS names, `ZEC`, `2Z`, `txid`, provider icon letters,
  ASCII numeric placeholders and the example email are identifiers/data.
- `src/lib/api/mock-data.ts`, `src/lib/wallet/mock.ts`, BIP-39 wordlists and test
  fixtures remain data. No fixture prose was translated. Controls describing a
  demo are UI, so their labels and explanations are translated.
- Source comments and non-rendered diagnostics are not catalog messages. The
  crash reporter's exact source-only log value is bound to its non-rendered
  call site. Rendering an Error/object message is checked, including values
  routed through local text helpers; UI error boundaries retain only safe keys.
- The exact technical values recorded in `extraction-policy.ts` are Tailwind
  class strings and the pending-donation storage key. This is not a directory
  exemption. No substring-based pseudo-locale exception remains.

## Regression checks and limits

`extraction-policy.test.ts` follows executable imports, explicitly skipping
truly type-only imports/exports while retaining mixed value imports and lazy
routes. It follows rendered values through local bindings, object fields and
text helpers. Constructors, comparisons and string methods are not blanket
exemptions for rendered prose. Negative controls cover Error/object strings,
join helpers, translated text helpers and diagnostics/templates moved into JSX.
It also rejects untranslated JSX/accessibility attributes and presenter literals,
and rejects module-scope translation calls. Mutation tests add a new lazy route,
rendered copy, descriptor, toast and template. Catalog checks reject missing,
orphaned, duplicate, malformed and invalid keys. Consumer checks run against the
production closure and reject declaration/comment-only substitutes. Translation
contracts also reject dropped/retyped ICU arguments, changed select branches,
missing/unbalanced markup and attributes in translation markup.

The AST policy is intentionally not a general React dataflow proof. Arbitrary
server content, recovery words and opaque identifiers can legitimately be
rendered; reviewing a new source of display data remains necessary. Its direct
sink and presenter checks complement runtime tests rather than treating every
string in a transport module as UI copy.

Run the focused policy/runtime tests with `npx vitest run src/i18n
src/lib/format.test.ts`; the standard frontend Vitest gate includes them.
`live-language.test.tsx` changes the instance language with Hero, Auth and
Wallet mounted, including existing owned errors and OTP/memo markup, without
remounting or changing entered data. `tests/i18n-kernel.pw.ts`,
`tests/i18n-features.pw.ts` (including live instance mutation), and existing Auth,
Wallet, About/feedback and payment browser specs cover the changed rendered
surface. Unit/browser mocks do not establish production payment or native
wallet readiness.

The original kernel build comparison was +94,672 raw/+29,509 gzip entry bytes.
That historical runtime measurement is not a new bundle measurement for this
extraction. Translation governance/TMS and native-speaker review remain ongoing
maintenance responsibilities.
