# ZUULI internationalization kernel

ZUULI uses `i18next`, `react-i18next`, and `i18next-icu`. ICU MessageFormat is
the catalog format because plural categories are locale data, not an English
singular/plural ternary. The first migrated plural is the mobile More-sheet
destination count; subsequent extraction slices must use the same ICU boundary.

`src/i18n/locale.ts` is the framework-neutral resolver ported from the legacy
Svelte client. Resolution prefers the existing persisted locale, then the
browser language, then English. This slice intentionally adds no writer or
language-setting control; that owner-gated product decision remains #326.

Each supported catalog (`en`, `es`, and `fr`) is loaded by its own dynamic
import. Catalogs have exact parity with `MESSAGE_KEYS`: CI mutations prove that
missing, orphaned, malformed, and invalid keys fail closed. Runtime lookup also
throws on a missing key instead of rendering the identifier or silently using
an incomplete fallback catalog. English, Spanish, and French shell/navigation
translations were seeded from `ts/svelte/free2z/src/lib/locales/` where the old
keys correspond; ZUULI-only messages use the same reviewed catalogs.

This is the first bounded slice of #325, not full extraction. It covers common
app shell, navigation, retry/not-found/root errors, and shared relative/date
formatting. Feature copy remains for later slices, mock fixture prose remains
deliberately excluded, and ZEC parsing/formatting remains ASCII-only and
locale-independent as required by #324.
